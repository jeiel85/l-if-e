# v0.2.0 상호작용 검증

검증일: 2026-10-15. Windows / Node.js 24 / agent-browser Chromium.

## 추가한 경험

- 장면 속 공책·창문·찻잔을 클릭해 기억 조각 수집. 같은 물건을 다시 눌러도 중복 수집하지 않음.
- 공책에 40자 이내 제목 입력, 세 컷의 순서 변경, 바꾼 순서로 미리보기 재생.
- 제목·컷 순서가 이후 장면, 엔딩, 기록 복사에 반영됨.
- 엔딩의 여섯 선택 지점 중 원하는 지점으로 돌아가 새 경로 시작.
- 이전의 완료 기록을 보관하고, 새 엔딩에서 달라진 선택과 후속 결과를 비교.

탐색과 공책 편집은 결말 도달 조건이 아니다. 기억 조각·컷 스케치·대사는 모두 창작이다.

## 자동 검증

`npm run check`, `npm test`, `npm run build` 통과. 10개 테스트이며, 기존 전체 729개 선택 조합의 도달 가능성 검증을 유지했다.

추가 테스트:

- 기존 v1 저장 구조를 유지하며 누락되거나 잘못된 공책 정보를 안전하게 정규화.
- 잘못된 컷 ID·중복 ID·문자열이 아닌 ID·잘못된 수집 목록 거부 또는 기본값 복원.
- 컷 이동의 순서·경계 처리와 원본 데이터 불변성.
- 여섯 복귀 지점 모두에서 앞선 선택만 보존하고 원래 기록을 복제해 독립시킴.
- 같은 번호의 선택을 해도 앞선 경로가 달라 결과가 달라진 장면까지 비교에 포함.
- 7개의 정적 배포 파일을 복사하고 원본과 바이트 일치 확인.

## 화면과 접근성

1440×1080 데스크톱과 390×844 모바일 뷰포트에서 확인했다. 모바일 문서 너비 390px, 공책 대화상자의 내용 너비·스크롤 너비 모두 356px로 가로 넘침이 없었다.

장면 탐색, 데스크톱·모바일 공책, 비교 엔딩의 axe-core 자동 검사에서 위반 0건을 확인했다. 배경 이미지 위 문구와 일부 짧은 기호의 대비는 자동 판정이 불완전하므로 육안으로 별도 확인했다. 이는 접근성 인증이 아니다.

탐색 지점과 컷 이동은 버튼으로 구현해 키보드로 조작할 수 있다. 입력창·대화상자가 열려 있을 때 숫자 키로 삶의 선택이 실행되지 않는다. 미리보기의 타이머는 공책을 닫거나 컷 순서를 바꾸면 정지한다. CSS는 동작 줄이기 설정을 반영한다.

실제 모바일 기기·Safari·Firefox·스크린 리더 청취 검증은 하지 않았다.

## 저장과 라이선스

기존 저장 키와 `version: 1`을 유지하고, 선택적인 `keepsakes`와 `fromChoices` 필드를 추가했다. 과거 기록에 없는 필드는 기본값으로 읽는다. 같은 여섯 선택으로 완성한 삶의 최초 기록은 덮어쓰지 않는다. 공책 입력은 기기 안에만 저장한다.
