# 첫 번째 삶 검증 기록

검증일: 2026-10-15. Node.js 24, Windows, agent-browser의 Chromium 환경.

## 자동 검증

- `npm run check`: 앱·시나리오·미리보기 서버의 JavaScript 문법 검사 통과.
- `npm test`: 6개 테스트 통과.
- 전체 **729개** 선택 조합에서 여섯 장면과 결말까지 도달함을 확인.
- 네 가지 결말이 모두 도달 가능함을 확인.
- 제작·글쓰기·일과 병행 경로에서 세 번째 사건이 실제로 달라짐을 확인.
- 이전 협의 경험에 따라 이후 의뢰의 합의 여부가 달라짐을 확인.
- 마지막 선택이 같아도 이전 작업·배움·감수한 것이 결말에 남음을 확인.
- 잘못된 선택, 불완전한 결말, 이전 버전·손상된 저장 구조 거부 확인.

## 실제 브라우저 플레이

1440×1080 데스크톱 화면과 390×844 모바일 뷰포트에서 확인했다. 모바일 검증은 Chromium의 화면 크기 조정이며 실기기 Safari 검증을 뜻하지 않는다.

| 시나리오 | 결과 |
| --- | --- |
| 시작 버튼 → 여섯 장면 → 결과 화면 | 정상 |
| 영화 제작 경로 → 작은 영화의 연출자 | 정상 |
| 글쓰기 경로 → 이야기를 쓰는 사람 | 정상 |
| 일과 병행 경로 → 두 개의 일상 | 정상 |
| 협업 선택 → 함께 만드는 사람 | 정상 |

| 결말 이후 새로고침 | 같은 결말·기록 복원 |
| 진행 중 숫자 키 `2` 선택 후 새로고침 | 선택의 결과 화면·선택값 복원 |

| 빗소리 버튼 | 재생·정지 상태 전환 확인. 청음에 의한 실제 음질 평가는 하지 않음 |

## 접근성 확인

처음 검사에서 발견한 보조 문구의 색상 대비를 수정했다. 수정 후 표지와 엔딩의 axe-core 검사에서 자동 판정 위반 0건을 확인했다. 배경 이미지 위의 일부 문구와 짧은 기호는 자동 대비 판정이 불완전하므로 육안으로 별도 확인했다. 이 결과는 전체 접근성 인증을 뜻하지 않는다.

키보드 포커스, 본문 바로가기, 숫자 키 선택, 네이티브 확인 대화상자, 동작 줄이기 CSS, 작은 화면의 레이아웃을 확인했다.

## 수정한 문제

- 빈 저장 상태에서 `/#play`로 직접 들어갈 때 중첩 렌더링으로 화면이 비는 경로를 수정했다.
- 표지의 두 열 높이가 달라 일러스트 아래 빈 공간이 남던 문제를 수정했다.
- 보조 텍스트 대비를 높였다.
- 자동 다운로드가 검증 브라우저에서 취소되어 내보내기 방식을 **기록 복사 + 권한 차단 시 텍스트 창**으로 바꾸고 두 경로를 확인했다. 실패하는 다운로드 버튼은 남기지 않았다.
- Windows 예약 포트와 충돌해 로컬 서버 기본 포트를 4317로 변경하고, 시작 실패 시 원인을 안내하도록 했다.

## 남은 검증 범위

실제 iOS·Android 기기, Firefox·Safari, 보조공학 프로그램과 저사양 기기의 장시간 플레이는 확인하지 않았다. 서버 계정·멀티 기기 동기화는 제품 범위에 포함되지 않는다.
